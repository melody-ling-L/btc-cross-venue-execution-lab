# 真实行情样本：来源、复现与解释范围

本实验使用 Tardis.dev 记录的 Binance Spot 与 Bybit Spot 历史五档盘口，订单、手续费、延迟与成交均在本地模拟。它回答的是“同一段行情在不同执行假设下会得到什么结果”，不提供真实成交记录或稳定盈利证明。

## 数据来源与本次窗口

| 项目 | 本次设置 |
| --- | --- |
| 标的 | 两所现货 BTCUSDT；`alpha` 对应 Binance，`beta` 对应 Bybit Spot |
| 行情日期 | 2026-10-01，UTC 每月第一日免费样本；本次下载于2026-11-08 |
| 类型 | `book_snapshot_5`，每侧最多五档的完整可见快照 |
| 导入窗口 | 供应商接收时间 2026-10-01 00:00:01.607699 至 00:10:01.607699 UTC，共600秒 |
| 毫秒决策边界 | 上述时间向上量化为 00:00:01.608 至 00:10:01.608 UTC |
| 纳入记录 | alpha 3,817条；beta 4,948条；合计8,765条，含beta一条起点前warmup |
| 截断 | 本次未触发100,000条事件上限；600秒窗口完成不表示导入了完整交易日 |
| 压缩文件 | Binance 13,728,600字节；Bybit Spot 20,797,707字节 |

600秒是数据选取窗口。模拟器在最后保留快照处结束：本次最早warmup接收时刻为00:00:01.574 UTC，最后事件为00:10:01.517 UTC，距选择窗口终点约91ms；不补造末尾行情或定时心跳。运行清单分别记录选取边界与实际保留事件边界。

原文件地址：[Binance样本](https://datasets.tardis.dev/v1/binance/book_snapshot_5/2026/10/01/BTCUSDT.csv.gz)、[Bybit Spot样本](https://datasets.tardis.dev/v1/bybit-spot/book_snapshot_5/2026/10/01/BTCUSDT.csv.gz)。覆盖范围可分别查看[Binance说明](https://docs.tardis.dev/historical-data-details/binance)与[Bybit Spot说明](https://docs.tardis.dev/historical-data-details/bybit-spot)。

## 从项目根目录复现

报告绘图依赖单独安装；模拟器、下载与导入使用Python标准库。

```bash
python3 -m pip install -r requirements-research.txt
python3 -m crossvenue sample \
  --day 2026-10-01 \
  --window-seconds 600 \
  --max-events 100000 \
  --pair-budget 100 \
  --order-qty 0.005 \
  --latency-ms 100 \
  --max-quote-age-ms 250 \
  --max-event-skew-ms 100 \
  --timeout 120 \
  --output outputs/real-sample
```

这条命令明确请求下载两份免费样本，不注册账户、不调用交易所账户或下单接口。完整且未超大小预算的gzip缓存通过CRC检查后复用；超时后重跑只请求缺失文件。损坏缓存或已有`.part`文件会报错并保留，程序不无限重试、不切换Bybit域名、不禁用TLS验证。遇证书错误应配置可信CA，不应关闭证书校验。

已有许可允许使用的本地文件时，可完全离线导入；参数与上面保持一致，并增加：

```bash
python3 -m crossvenue sample \
  --day 2026-10-01 \
  --input-files \
    data/tardis-private/2026-10-01/binance_book_snapshot_5_2026-10-01_BTCUSDT.csv.gz \
    data/tardis-private/2026-10-01/bybit-spot_book_snapshot_5_2026-10-01_BTCUSDT.csv.gz \
  --window-seconds 600 --max-events 100000 --pair-budget 100 \
  --order-qty 0.005 --latency-ms 100 \
  --max-quote-age-ms 250 --max-event-skew-ms 100 \
  --output outputs/real-sample
```

主要输出是`research_report.html`、`research_report.md`、`results.json`和`run_manifest.json`。原gzip、`normalized.private.jsonl`和私有来源清单保存在被Git忽略的`data/`下。默认`outputs/`也被忽略；准备发布时只选取已审查的汇总研究结果。

## 时钟与可见性

`local_timestamp`是Tardis采集服务器的接收时刻，单位为UTC epoch微秒，不是作者北京电脑的接收时刻。它不能代表作者到交易所的网络延迟。`timestamp`保留供应商给出的交易所时钟；供应商文档说明缺失时可能回退为接收时间，导入器不额外伪造交易所时间。[字段定义](https://docs.tardis.dev/downloadable-csv-files/data-types)

导入器按供应商接收微秒与原始行序合并；发现已读取部分的接收时间倒退会报错，不先排序掩盖问题。`sequence`是源CSV行序号，不是交易所更新序号，不能用它研究交易所丢包。

为匹配模拟器的毫秒批处理，`recv_ms = ceil(local_timestamp / 1000)`。同一毫秒桶的所有消息在桶末才用于决策；实际微秒另存，但不声称具备亚毫秒执行精度。交易所事件毫秒保持向下取整，只用于声明的事件时效检查。两源共同起点之前各最多保留一条warmup，建立当时已知盘口。

## 本次模型假设

| 模型 | 深度 | 每侧手续费 | 额外订单延迟 | 信号与限制 |
| --- | --- | --- | --- | --- |
| screen | 最优价容量乐观放大至至少一单 | 0 | 0ms | 毛价差入场 |
| fees | 同上 | 10bps | 0ms | 毛价差入场，成交后实际扣费 |
| depth | 已知五档内按数量计算 | 10bps | 0ms | 毛价差入场 |
| latency | 已知五档内按数量计算 | 10bps | 100ms | 毛价差入场，独立模拟两腿 |
| guarded | 已知五档内按数量计算 | 10bps | 100ms | 净价差入场、报价年龄与跨所时钟偏差检查、残余BTC限额 |

10bps等于每腿成交金额的0.1%，为统一教学假设，不是已核实的历史账户或当前交易所费率。费用统一以USDT扣除，每笔成交只记一次，不从最终损益再次重复减费。100ms是额外模拟订单延迟，不是测量得到的交易所往返延迟。

每单目标0.005 BTC，每个模型最多提交100对；初始每所10,000 USDT和0.1 BTC，不能借币或瞬时跨所转账。`guarded`的报价年龄上限250ms、交易所时钟偏差上限100ms、残余BTC停止新增阈值0.005 BTC、净优势门槛严格大于0bps。停止新增不会自动对冲或平掉已存在的单腿风险。

每对IOC限价由决策时已知盘口固定，延迟后使用当时已接收的盘口尝试成交。虚拟成交消耗的深度在下一份快照到来时重置；历史市场没有响应这个虚拟交易者，重置不能证明同一流动性可反复交易。只有一对订单可同时等待成交，各模型也可能选择不同交易集合，因此模型间差异不是严格可加的成本归因。

共同起末估值是两所最新已知最佳买卖中价的平均值，仅用于同口径账本估值，不是退出成交价。原有BTC库存产生的方向损益与相对持有基准的执行贡献在本地私有账本分别计算；真实来源公开报告去除精确库存损益、权益和余额，只保留允许的粗化执行汇总。

## 本次汇总结果如何解读

以下均为这600秒样本及上述假设下的模拟结果，金额单位USDT：

| 模型 | 提交对数 | 双腿足量对数 | 单腿对数 | 已记手续费 | 相对持有基准的执行贡献 |
| --- | ---: | ---: | ---: | ---: | ---: |
| screen | 100 | 100 | 0 | 约0 | 约+1 |
| fees | 100 | 100 | 0 | 约84 | 约-82 |
| depth | 100 | 100 | 0 | 约84 | 约-82 |
| latency | 100 | 84 | 16 | 约77 | 约-76 |
| guarded | 0 | 0 | 0 | 0 | 0 |

真实来源的公开执行贡献与费用粗化到1 USDT，额外BTC粗化到0.001 BTC；不公开逐所余额、权益、总损益或库存方向损益数值，避免单对精确现金流反推出成交均价。精确账本恒等式在导出前检查；公开值经过舍入，不能用于逐分对账。

`screen`等模型达到100对提交上限，不是当天所有机会统计。`latency`出现16对单腿完成，最大额外BTC为0.010；其执行贡献比`depth`少亏，也不能据此断言延迟有益，因为成交集合、单腿数量与终值敞口均不同。

`guarded`零交易表示本样本没有通过其完整入场条件的提交，不说明不存在其他策略。它仍持有最初0.2 BTC，继续承担库存的方向风险；执行贡献为零不等于账户总损益为零。精确账本恒等式通过，只说明算术自洽。

## 许可与研究边界

依据[2026-10-28版Tardis条款](https://docs.tardis.dev/legal/terms-of-service)第1、9节，免费样本同样受数据许可约束。原始行情、仅改格式或抽样后的逐tick数据不提交GitHub；公开报告限于条款允许的不可还原汇总图表、统计和研究文字。不把真实样本嵌入公共逐tick回放工具，不发布基于这些数据训练的模型权重。代码和合成测试夹具可独立复现机制。

这份样本还存在以下限制：

- 每侧只有五档，不能推断更深流动性、隐藏订单或真实队列位置；它不是bookTicker，也不是交易所全部深度。
- 快照由供应商从L2重建并清理交叉档位；CSV不包含断连事件，记录到达也不能证明全段行情完整无误。[CSV说明](https://docs.tardis.dev/downloadable-csv-files/api)
- 模拟成交没有真实订单确认、撮合回报或资金流水；没有验证交易所最小数量、价格步长、交易优先级与实际冲击。
- 仅取一个月首交易日开头的十分钟，存在日期、时段与市场状态选择偏差；不外推长期收益、不年化Sharpe、不据此选择“最佳收费或延迟”当成可交易优势。
- 固定资金预置、没有再平衡转账成本、借贷、资金费、自动对冲及交易所信用损失模型；风险管理能力仅限声明的模拟范围。

可用于面试的结论是：看似正的屏幕价差，在这一段样本与固定费用假设下会被成本和执行约束显著改变；项目记录了数据、时钟、账本与未知状态的处理方法。它没有证明一条可实盘盈利的套利策略。
