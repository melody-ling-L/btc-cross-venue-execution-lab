## 第一步独立复测

以下全是新的合成教学数据。假设双腿足额成交，手续费均以 USDT 扣除，无其他成本。

| 项目 | A 所 | B 所 |
| --- | --- | --- |
| 初始 USDT | 8,000 | 0 |
| 初始 BTC | 0 | 0.1 |
| 本次操作 | 按 ask 100,000 买入 0.03 BTC | 按 bid 100,200 卖出 0.03 BTC |
| 手续费率 | 0.1% | 0.1% |

先不看参考账本，写出：A 剩余现金、B 卖出净到账、本次双腿净执行损益。保留中间步骤，不按近似费率提前四舍五入。

## 第二步独立写函数

补全同目录 `day02_net_pnl.py` 的 `net_execution_pnl`。也可以先在聊天里提交函数主体，再写进文件。

| 参数 | 含义与单位 |
| --- | --- |
| `qty` | 双边相同的成交 BTC 数量 |
| `buy_ask` | 买入成交价格，USDT/BTC |
| `sell_bid` | 卖出成交价格，USDT/BTC |
| `buy_fee_rate` | 买入费率，小数形式 |
| `sell_fee_rate` | 卖出费率，小数形式 |

函数返回净执行损益，单位 USDT。先写清买入金额、买入手续费、卖出金额和卖出手续费，再组合现金流。费用必须分别按两边各自的成交金额计算。

输入采用 `Decimal("0.001")` 这样的字符串构造。0.1% 对应 0.001。今天先假设输入有效，不扩展盘口、部分成交或交易接口。

## 第三步验收与解释

函数写好后，用同一组价格和数量分别运行三组费用：双方费用都为 0；双方都为 0.001；买入 0.0005、卖出 0.001。

每组先独立预计结果，再运行。解释哪个现金流改变了，结果为什么相应变化。最后再与参考账本比较。

## 本节范围

这里只计算已确认双腿等量足额成交后的现金流贡献，不计算初始 BTC 库存涨跌，也不证明真实机会可以成交。手续费若改成从 BTC 扣除，持仓数量和账本都会变化，不能直接沿用本题的 USDT 费用约定。

## 第四步检查 BTC 扣费后的数量

改一个教学条件：A 买入 0.03 BTC，手续费按买入数量的 0.1% 从 BTC 扣除；B 初始有 0.1 BTC，卖出 0.03 BTC，卖出手续费仍用 USDT 支付。双腿均已足额成交，没有其他 BTC 变动。

先分别写出 A 实际到账和 B 实际卖出的 BTC 数量，再回答：

1. 本次两所合计 BTC 数量相对交易前增加或减少多少？
2. 若希望本次总 BTC 数量保持不变，B 应卖出多少 BTC？

本题检验成交数量与扣费后到账数量的区别。现有 `net_execution_pnl` 的 USDT 扣费假设保持不变；涉及 BTC 费用时，要另行记入资产账本。

## 第五步把 BTC 数量变化写成函数

`day02_net_pnl.py` 中的 `net_btc_change` 根据学习者纠正后提交的表达式封装。它分别接收买入成交量、卖出成交量及买入费率，假设买入费用以 BTC 扣、卖出费用以 USDT 扣，返回本次 BTC 数量变化。

验收场景为：等量买卖但从 BTC 扣费、等量买卖且零费率、卖出量等于扣费后到账量。它只计算数量变化，不替代 USDT 损益函数，也不处理真实订单、部分成交过程或其他费用币种。

能否仅凭 USDT 增加就说交易赚钱？请计算两种资产合计的权益变化，并解释 BTC 减少怎样影响结果。
